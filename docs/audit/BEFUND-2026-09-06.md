### 🟠 MAJOR

#### M2: 7 useMutation ohne onError-Handler (stille Fehler)

**Severity:** MAJOR — User sieht keine Fehlermeldung bei Mutation-Fehlern
**Dateien:**

- `src/app/dashboard/admin/eval-review/page.tsx`
- `src/app/dashboard/admin/feedback-triage/page.tsx` — hat `decideMutation.isError` im Dialog, aber kein `onError` callback
- `src/app/dashboard/agents/page.tsx`
- `src/components/dashboard/corpus-steward/PublishBanner.tsx`
- `src/components/dashboard/sidebar.tsx`
- `src/components/mobile/mobile-sync-banner.tsx`
- `src/lib/matter-detail-context.tsx`

**Problem:** 7 von 92 `useMutation` calls haben keinen `onError`-Handler. Bei Mutation-Fehlern bleibt die UI stumm — der User bekommt kein Feedback. AGENTS.md sagt: "Toast bei JEDEM Mutation-Erfolg UND -Fehler".

**Fix:** `onError` callback mit `addToast({ type: "error", ... })` hinzufügen, oder sicherstellen dass `mutation.isError` in der UI gerendert wird.

### 🟡 MINOR

#### m1: 37 dashboard subroutes ohne error.tsx (parent covers)

**Severity:** MINOR (parent `dashboard/error.tsx` covers via hierarchy)
**Details:** 37 dashboard subroutes haben keine eigene `error.tsx`. Next.js error boundaries sind hierarchisch — `dashboard/error.tsx` fängt alle Errors in subroutes ab. Das ist funktional OK, aber spezifischere Error-UIs wären besser (z.B. admin-spezifische Fehlermeldung).

#### m2: 57 useQuery ohne staleTime (over-fetching)

**Severity:** MINOR (Performance)
**Details:** 57 `useQuery` calls, nur 18 haben `staleTime` gesetzt. Default `staleTime: 0` bedeutet jeder Component-Mount triggert einen Refetch. Bei teuren Queries (z.B. corpus-meta, agent-jobs) sollte `staleTime: 30_000` oder höher gesetzt werden.
**Fix:** Default `staleTime` in QueryClient config setzen, oder pro Query.

#### m3: 633 inline styles (style={{}})

**Severity:** MINOR (Design-System-Konsistenz)
**Details:** 633 inline `style={{}}` in production code. Viele sind legitim (dynamische Werte wie Graph-Node-Positionen), aber einige könnten via Tailwind classes ersetzt werden.
**Fix:** Audit der inline styles — dynamische Werte behalten, statische via Tailwind.
